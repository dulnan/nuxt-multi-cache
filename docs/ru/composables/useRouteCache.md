# useRouteCache

Доступен в **Nuxt** и **Nitro**.

Этот composable доступен когда [функция Route Cache](/ru/features/route-cache) включена. Он позволяет вам контролировать, должен ли текущий запрос кешироваться и как.

## Полный пример

```typescript
useRouteCache((helper) => {
  helper.setMaxAge(3600).setCacheable().addTags(['page:1'])
})
```

## Аргументы

### callback?: `(cache: NuxtMultiCacheRouteCacheHelper) => void`

Callback, который получает route cache helper. Callback вызывается только на сервере.

### event?: `H3Event`

Опциональный `H3Event` event. Не требуется, когда composable вызывается в контексте Nuxt приложения (например, плагин, другие composables, компонент).

При вызове в серверном контексте Nitro аргумент обязателен.

## Методы

### setCacheable()

Вызов этого метода установит ответ как кешируемый. Обратите внимание, что если ранее был вызван `setUncacheable()`, то этот метод ничего не делает. Таким образом мы можем убедиться, что, например, конфиденциальная информация от аутентифицированных пользователей никогда не кешируется.

### setUncacheable()

Пометить ответ как некешируемый. Это решение окончательное и не может быть отменено. Обычно это используется для предотвращения кеширования конфиденциальной информации от аутентифицированных пользователей или для предотвращения кеширования сломанных страниц.

**Пример:** Запрос к внешнему API не выполнен, и компонент не может отрендерить данные. Предотвращаем кеширование страницы в этом сломанном состоянии.

```vue
<template>
  <div v-if="weather">
    <!-- Рендер Weather -->
  </div>
  <div v-else>
    <p>Погода в данный момент недоступна.</p>
  </div>
</template>

<script lang="ts" setup>
const { data: weather } = await useAsyncData('weather', () => {
  return $fetch('/api/getWeather').catch(() => {
    // Предотвращаем кеширование страницы, потому что этот компонент
    // не смог загрузить свои данные.
    useRouteCache((v) => v.setUncacheable())
  })
})
</script>
```

Альтернативно вы также можете просто уменьшить max age для страницы, чтобы через 5 минут страница была отрендерена снова.

### setMaxAge(maxAge: number)

Установить max age в секундах для записи кеша. После этого страница рендерится снова.

Обратите внимание, что записи кеша остаются в кеше после истечения. Когда они истекают, маршрут рендерится снова, и ответ перезаписывает устаревшую запись кеша.

### setStaleIfError(maxAge: number)

Установить "stale if error" в секундах для записи кеша. Когда установлено, устаревший кешированный маршрут (другими словами, запись кеша, которая обычно не будет обслужена, потому что она истекла) будет обслужена, если во время рендеринга возникает ошибка 5xx.

### allowStaleWhileRevalidate()

Разрешить обслуживать устаревший кешированный ответ, пока новый "ревалидируется" (генерируется/рендерится).

Например, если у вас есть страница, которая делает внешний API вызов, занимающий много времени, вы можете предотвратить "бомбардировку" этого API, выполняя только один запрос за раз. Если эта страница становится устаревшей и если 10 человек запросят эту страницу одновременно, вы вызовете 10 API вызовов. Установив `allowStaleWhileRevalidate`, только первый запрос вызовет API вызов, а остальные 9 получат устаревший ответ. После завершения первого запроса каждый последующий запрос будет получать новый, свежий ответ.

### addTags(tags: string[])

Добавить cache tags для записи кеша. Они могут быть позже использованы для очистки конкретных элементов кеша.

**Пример:** Вы можете добавить cache tag на основе текущего языка страницы: `language:de`. Позже, если некоторые переводы изменятся, вы можете инвалидировать все кешированные страницы на немецком:

```bash
curl -X POST -i -H "Content-Type: application/json" \
  --data '["language:de"]' \
  http://localhost:3000/__nuxt_multi_cache/purge/tags
```

### Свойства экземпляра

Helper имеет три свойства для отслеживания состояния:

- `tags: string[]`
- `cacheable: boolean|null`
- `maxAge: number|null`
- `staleIfError: number|null`

Хотя это абсолютно не рекомендуется, вы можете напрямую манипулировать этими значениями для специфических крайних случаев.
