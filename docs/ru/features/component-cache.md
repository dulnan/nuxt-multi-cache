# Component Cache

- Кеширует отрендеренную разметку компонентов
- Работает в SSR (серверный рендеринг) и SSG (статическая генерация сайта)
- Поддерживает кеширование payload для компонента
- Минимальное влияние на размер клиентского бандла
- Компонент должен иметь имя, чтобы быть кешируемым

Компонент RenderCacheable - это обертка для кешируемых Vue-компонентов. Он позволяет кешировать содержимое default slot на основе props первого дочернего элемента в слоте. Альтернативно, вы можете предоставить пользовательский ключ кеша.

На сервере содержимое default slot будет закешировано как разметка. После этого рендеринг пропускается, и разметка отображается напрямую.

::: warning

Из-за [бага в Vue](https://github.com/vuejs/core/issues/6207) в настоящее время невозможно использовать `<Teleport>` вместе с `<RenderCacheable>` (или любым другим async компонентом).

:::

Кешируемость компонента также может быть установлена динамически с помощью composable [useComponentCache](/ru/composables/useComponentCache).

## Требования

- Slot может содержать только один компонент
- Вы можете кешировать только компонент, а не любые другие типы шаблонов
- Если нужно рендерить компонент условно, поместите `v-if` на `<RenderCacheable>`, **а не** на кешируемый компонент
- **Не изменяйте** глобальное состояние из кешированных компонентов, так как код [выполняется только один раз](#caveats)

## Конфигурация

::: code-group

```typescript [nuxt.config.ts]
import { defineNuxtConfig } from 'nuxt'

export default defineNuxtConfig({
  multiCache: {
    component: {
      // Если true, кеш включен.
      // Если false, кеш отключен, но компонент все равно добавлен в сборку.
      enabled: true,
    }
  }
}
```

```typescript [multiCache.serverOptions.ts]
import { defineMultiCacheOptions } from 'nuxt-multi-cache/server-options'
import myCustomDriver from './somehwere'

export default defineMultiCacheOptions(() => {
  return {
    component: {
      storage: {
        driver: myCustomDriver(),
      },
    },
  }
})
```

:::

## Использование

```vue
<template>
  <div>
    <RenderCacheable>
      <Navbar />
    </RenderCacheable>
  </div>
</template>
```

Содержимое default slot рендерится только один раз, и результирующая разметка кешируется. Каждый последующий запрос будет напрямую возвращать кешированную разметку и пропускать рендеринг.

## Ключ кеша

Поскольку компонент рендерится только один раз, он не может полагаться на внешнее состояние. Это означает, что следующие функции _обычно_ не должны использоваться в кешированном компоненте (список не исчерпывающий):

- Глобальное состояние (useState)
- Pinia (useStore)
- Router (useRoute)
- Meta (useHead)
- Request (useRequestHeaders, useRequestEvent, useCookie)

Однако вы можете использовать любое из этого в родительском компоненте и передавать значения через props.

Например, если вы используете интернационализацию, ваш компонент будет рендериться по-разному в зависимости от текущего языка. Это означает, что ключ кеша должен это учитывать:

```vue
<template>
  <div>
    <RenderCacheable>
      <Navbar :language="currentLanguage" />
    </RenderCacheable>
  </div>
</template>
```

Ключ кеша автоматически формируется из имени компонента и props. Props хешируются и добавляются к имени компонента:

```
Navbar::voBC1hkg5S
```

Это означает, что для каждого возможного языка генерируется разный ключ кеша.

### Пользовательский ключ кеша

Вы также можете предоставить свой собственный ключ кеша:

```vue
<template>
  <div>
    <RenderCacheable :cache-key="[currentLanguage, currentCurrenсy].join('--')">
      <Navbar />
    </RenderCacheable>
  </div>
</template>
```

Результирующие ключи записей кеша будут примерно такими:

- `Navbar::en--usd`
- `Navbar::de--chf`
- `Navbar::fr--eur`

## Cache Tags

Вы можете предоставить пользовательские cache tags, которые позже можно использовать для удаления компонентов из кеша:

```vue
<template>
  <div>
    <RenderCacheable :cache-tags="['navbar']">
      <Navbar :language="language" :currency="currency" />
    </RenderCacheable>
  </div>
</template>
```

Предположим, что есть много комбинаций языка и валюты, в итоге вы получите десятки записей кеша для этого компонента. Но поскольку все они имеют один и тот же cache tag (`navbar`), вы можете удалить их все из кеша сразу, очистив по cache tag:

```bash
curl -X POST -i \
  -H "Content-Type: application/json" \
  --data '["navbar"]' \
  http://localhost:3000/__nuxt_multi_cache/purge/tags
```

## Max Age

Вы можете кешировать компоненты только на ограниченное время, определив max age в секундах:

```vue
<template>
  <div>
    <RenderCacheable :max-age="3600">
      <Navbar :language="language" :currency="currency" />
    </RenderCacheable>
  </div>
</template>
```

Здесь компонент будет отрендерен снова после прошествия 1 часа. Обратите внимание, что записи кеша не удаляются автоматически при истечении. Они будут перезаписаны при следующем рендеринге.

## Извлечение Payload

Если кешированный компонент загружает данные с использованием useAsyncData или useFetch, вы должны сообщить `<RenderCacheable>`, какие ключи payload извлекать.

Предположим, у вас есть следующий компонент Weather:

```vue
<template>
  <div>
    <!-- Рендер Weather -->
  </div>
</template>

<script lang="ts" setup>
const { data: weather } = await useAsyncData('weather', () => {
  return $fetch('/api/getWeather')
})
</script>
```

Мы используем ключ `weather` в `useAsyncData`. Поэтому мы должны предоставить тот же ключ:

```vue
<template>
  <div>
    <RenderCacheable :async-data-keys="['weather']">
      <Weather />
    </RenderCacheable>
  </div>
</template>
```

Теперь после первоначального рендеринга соответствующий payload с ключом `weather` извлекается и кешируется вместе с компонентом. Каждый последующий запрос теперь будет возвращать кешированную разметку _и_ добавлять payload в ответ.

## Пропуск кеширования

Используя prop `noCache`, вы можете пропустить кеширование для компонента. Примером может быть ситуация, когда наш компонент Navbar показывает конфиденциальную информацию, например email пользователя. Установка `:no-cache="false"` гарантирует, что компонент не будет извлечен из кеша и также не будет помещен в кеш.

## Все Props

```vue
<template>
  <div>
    <RenderCacheable
      tag="aside"
      :async-data-keys="['weatherData']"
      :cache-tags="['weather', 'global']"
      :cache-key="language"
      :no-cache="userIsLoggedIn"
    >
      <Weather />
    </RenderCacheable>
  </div>
</template>
```

### `tag (string, по умолчанию: 'div')`

Тег для использования в обертке. К сожалению, невозможно реализовать это без обертки.

### `noCache (boolean, по умолчанию: false)`

Полностью отключить кеширование для этого компонента.

### `cacheKey (string, по умолчанию: '')`

Ключ для использования в записи кеша. Если оставить пустым, ключ автоматически генерируется на основе props, переданных дочернему элементу. Ключ автоматически добавляется с префиксом имени компонента.

### `cacheTags (string[], по умолчанию: [])`

Cache tags, которые позже можно использовать для инвалидации.

### `asyncDataKeys (string[], по умолчанию: [])`

Предоставьте ключи async data, используемые кешированным компонентом. Если предоставлены, данные payload будут кешироваться вместе с компонентом. Если компонент использует asyncData, а ключи не предоставлены, вы получите ошибку hydration mismatch на клиенте.

## Предостережения

Имейте в виду, что код компонентов, обернутых в `<RenderCacheable>`, выполняется только один раз - после этого используется только их кешированная разметка.

Это означает, что вы должны избегать зависимости от глобального состояния в ваших компонентах, если только вы не изменяете ключ кеша соответственно. Вы также не должны определять или изменять глобальное состояние из компонента каким-либо образом, так как это вызовет неожиданное поведение.

## За кулисами

В Vue 2 / Nuxt 2 кеширование компонентов было интегрировано в vue-server-renderer с использованием метода `serverCacheKey` на компонентах. Эта функция была удалена в релизах V3, поэтому пришлось найти альтернативное решение.

Компонент `<RenderCacheable>` использует метод `ssrRenderSlotInner` из `vue/server-renderer` для получения отрендеренной разметки и сохраняет ее в кеше. Затем эта разметка возвращается как render функция:

```typescript
return () => h('div', { innerHTML: cachedMarkup })
```

Это работает достаточно хорошо. На клиенте компонент рендерится нормально. Этот подход имеет те же ограничения, что и раньше: Кешированные компоненты не могут получать или устанавливать какое-либо глобальное состояние, и они должны рендериться одинаково для данных props.
